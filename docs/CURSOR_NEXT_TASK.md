# CURSOR_NEXT_TASK.md

## Objective

Transform PropertyPilot from a collection of pages into an engine-driven platform.

Do not redesign the existing workflow.

Keep all existing APIs and functionality working.

---

# Build These Services First

## 1. PropertyDNAService
Create one normalized Property DNA object.

Everything writes to it.

Everything reads from it.

No feature should parse MLS, documents, photos, or voice notes independently.

---

## 2. QuestionAnsweringService

Input:
- Property DNA
- Selected room
- Buyer question

Output:
- Answer
- Confidence
- Source references
- Needs follow-up flag

Never invent information.

---

## 3. AssetGenerationService

Generate every asset from Property DNA.

Required assets:

- Feature Sheet
- Buyer Brochure
- Open House Flyer
- MLS Description
- Luxury Description
- QR Sign
- Buyer FAQ
- Showing Notes
- Voice Introductions

Every asset must support regeneration.

---

## 4. BuyerActivityService

Record:

- QR scans
- Room selected
- Questions
- Leads
- Downloads
- Session timestamps

No advanced analytics yet.

Just capture the data.

---

## 5. RecommendationService

Analyze Property DNA and Buyer Activity.

Generate recommendations such as:

- Missing roof information
- Missing HVAC information
- Buyers repeatedly asking the same question
- Recommend new FAQ
- Recommend new brochure section
- Recommend different hero image

---

## 6. PublishingService

Responsible only for:

- Public property pages
- QR tours
- Room QR links
- Publish / Unpublish

---

## 7. GHLSyncService

Keep this isolated.

Synchronize:

- Contacts
- Notes
- Tasks
- Tags

Do not mix GHL logic into other services.
